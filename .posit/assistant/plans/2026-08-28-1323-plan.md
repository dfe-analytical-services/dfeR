# Diagnosis: `test-air_formatter.R` failure

## Root cause

The test expects Air to rewrite `=` assignment as `<-`:
```
"test_function <- function(\n  param = NULL\n) {\n  print(\n    param\n  )\n}"
```
but the actual output keeps `=`:
```
"test_function = function(\n  param = NULL\n) {\n  print(\n    param\n  )\n}"
```

This is explained by a change in Air itself, not in this package's R code:

- Air 0.10.0 introduced the `assignment-style` option. Its **default value changed from the old implicit "preserve" behavior to `"arrow"`**, meaning as of 0.10.0+, running `air format` on `x = y` now rewrites it to `x <- y` by default.
- The Air executable currently installed on this machine (`%USERPROFILE%\.local\bin\air.exe`) is **version 0.8.1**, which predates this change and therefore preserves `=` as-is — matching the "actual" output seen in the failing test.
- `air_install()` in [R/air_formatter.R](R/air_formatter.R) only installs Air if the executable is **absent** (`file.exists(...)` check); it never checks whether an already-installed Air is out of date. So a previously installed 0.8.1 binary is never upgraded, and the test (written assuming current/latest Air defaults) now fails against that stale binary.

In short: the test's expectation is correct for current Air versions; the local Air install is simply outdated and `air_install()` has no upgrade path for existing installations.

## Proposed fix

1. **Upgrade the local Air binary** used for running tests (one-time, environment-level fix) so `air --version` reports 0.10.0+ — this alone should make the existing test pass without any source changes, since it removes the environment/version mismatch.
2. **Harden `air_install()`** in [R/air_formatter.R](R/air_formatter.R) so it doesn't silently skip installation forever once any version is present. Options (pick one, or combine):
   - Add a version check: parse `air --version` output and compare against the latest GitHub release tag; reinstall if older.
   - Add a `force = FALSE` parameter to `air_install()` that, when `TRUE`, always runs the installer regardless of existing installation.
3. **Make the test version-resilient** (optional but recommended) so future Air default changes don't silently break CI:
   - Explicitly pin the formatting behavior the test relies on, e.g. by writing a temporary `air.toml` in the test's temp dir with `assignment-style = "arrow"` before calling `air_style()`. This decouples the test from Air's evolving defaults.
   - Alternatively/additionally, assert `air --version` meets a minimum supported version at the top of the test (skip with a clear message if not), so failures point directly at the environment rather than looking like a code regression.
